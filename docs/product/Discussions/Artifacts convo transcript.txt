## Assessment delivery — core rule

All assessment triggers live in the chat thread as a card/CTA. From there,
the experience branches based on the test type:

| Test | Delivery | Notes |
|---|---|---|
| Work preference | In-app, full-screen or bottom sheet | Pairwise ranking; ~20–30 questions |
| Holland (interest assessment) | In-app, full-screen or bottom sheet | Built internally |
| Values assessment | In-app, selection-based | Predefined options, inside app |
| MBTI | External for now; eventually in-app | Only test that routes out of app |
| Industry preferences | In-chat bottom sheet | ~16 predefined options, multi-select |
| Hobbies / obsessions | In-chat, free text | Self-reported, short answer |
| Opportunities & threats | In-chat bottom sheet | 7 survey questions (country, work type, risk) |
| Skills audit | In-app, AI-assisted selection | User gives job title → AI generates responsibilities → user selects |

Rule of thumb: long/complex test → full-screen or bottom sheet. Short/simple
answer → inline chat or quick bottom sheet. External only: MBTI (for now).


## Assessment UX — key decisions

- CTA in chat always. The in-chat card is the trigger; the test itself opens
  as full-screen or bottom sheet from there.
- Two CTA states on the in-chat card: "Take the test" (not done yet) and
  "Enter result" (already done externally — only relevant for MBTI).
- Resume on return: if a user exits mid-test, re-entering the app should
  show a "Continue where you left off" prompt for that test.
- Re-taking is allowed. Results can change (e.g. MBTI shifts are common).
  Don't lock to first result.
- Card design in chat should be visually distinct and beautiful — referenced
  the Career Discovery card style.


## Skills audit — specific flow

1. User provides job title (or uploads resume).
2. AI generates 10 role-specific responsibilities.
3. User selects which ones apply to their experience.
4. AI infers skill profile from selections — no manual reflection required.
Goal: reduce mental load; surface experience people don't realise they have.


## Assessment state

- All tests save progress locally (on device) and to backend.
- Mid-completion state should persist across sessions.
- MBTI: one output, one selector ("this is my result") — no complex scoring
  logic needed on our side for the external version.
- Backend (Django): Emmanuel to build backend hooks for each test. UI to be
  built now and connected once backend configs are ready.


## In-app vs external — rationale

Routing users externally risks losing them and makes result capture fragile
(extension approach was tried, caused friction). Building tests internally
gives full control over UX, timing, and result ingestion. MBTI is the only
exception for now due to complexity — open-source MBTI implementation being
explored.

## Assessment delivery — web vs. mobile

The in-chat card is always the trigger (consistent with meeting decisions above).
Once tapped, the assessment opens in full-screen on both web and mobile (bottom
sheet is the mobile-native variant of the same pattern). The current playground
prototype shows assessment inputs inline in the chat thread — that is a
prototype convenience only and does not reflect the intended UX.

Rule: in-chat card triggers → full-screen assessment experience → result
returned to chat on completion.


## Pillar / session architecture

- Each curriculum pillar = a separate chat session.
- Sessions are grouped under "Career Clarity" in the sidebar.
- Pillars are sequential — completing one unlocks the next.
- Locked sessions are navigable: show the module description and a locked
  input ("Finish the previous session to unlock this one").
- Completed sessions move to the bottom of the section list with a round
  check icon.
- After the final pillar of a module is completed, the next module becomes
  the active section in the sidebar. The completed module (e.g. Career
  Clarity) is preserved on the curriculum page for historical reference.


## Session completion moment

- Input box transforms into a "Continue to [Next Topic]" CTA when the final
  artifact of a session is complete. No continued chatting is allowed after
  session end — the input is fully blocked.
- Confetti ruled out (cliché).
- Design recommendation: badge drop-in — round check badge animates down
  with elastic bounce above the input zone, then lifts away as the CTA fades
  in. The same check icon simultaneously fills in on the sidebar session
  item. Mockup built and demoed. Decision pending confirmation.


## Curriculum page

- Central place for all curriculum-related data and module history.
- Lists all modules in the active programme; sequential — completing one
  unlocks the next.
- Active module: accessible and visually highlighted.
- Inactive / upcoming modules: visible but locked (description shown, not
  enterable).
- Completed modules remain visible as historical record.
- Sidebar persists — curriculum is an in-page view, not a separate route.

## Artifact engine bug fix (resolved)

- 5 artifact types (holland, craft, self-report, research-action,
  external-assessment) were returning null after completion — Mande went
  silent with no follow-up.
- Fixed: all 5 now have acknowledgment messages; toResponseType covers all
  9 artifact types with correct return type.
